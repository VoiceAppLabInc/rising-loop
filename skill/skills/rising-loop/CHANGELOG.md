# CHANGELOG

このスキルは Rising Loop に同梱されていて、アプリの更新で新しくなります。版の正は `VERSION` です。
**「移行が必要」** と書かれた版は、既存プロジェクトの `loops/` に手が要ります。古い形はアプリが見分けて知らせ、ユーザーが［新しい形にする］を押したときだけ直します。古い形のままだと、AI の作業がうまく動かないことがあります。

## 2.0.0 — 2026-10-01

**移行が必要**（画面の枠と共通の部品の入れ替えだけ。各ページの数字・施策・記録には触らない）

- ★ **Rising Loop App に同梱する形にした。** スキルの場所は、読み込んだときに示されるフォルダ（SKILL.md では `<スキル>`）。
  `~/.claude/skills/rising-loop` に入れて使う形はやめた
- **右のチャットはアプリが出す。** `ttyd` と `chat-pane.sh` は使わない。ボタンの指示文はアプリがチャットに送るので、コピーして貼る手間が無くなった
- **画面はアプリが読み込み直す。** AI が `loops/` を書き終えると自動で変わるので、「画面を再読み込みしてください」と言わない
- **更新はアプリの更新で届く。** `install.sh` と、GitHub の `VERSION` を見に行く確認をやめた。
  「最新版に合わせる」で親がやるのは、枠の入れ替えとマーケター向けの欄を見せるの2つになった
- ★ **新しい形に合わせるのは、ユーザーが選んだときだけ。** 版の違いに気づいても、AI は自分から合わせない。
  版はアプリが見分けて知らせる
- ★ **入れ替えと控えはアプリがやる。** 殻の作り直し・共通の部品の上書き・控え（`loops/` の外）はアプリの決まった処理。
  AI には「新しい形への作り直し」の作業として、台帳の項目のうちまだ反映していないもの（頁ごと・一覧）と、殻から消えた独自の部品だけが届く。
  AI は `shell-update.py` を流さない。アプリが扱うのは 1.5 以上の形だけ
- ★ **台帳 `migrations.json` を足した。** 版ごとに、既存のループの HTML に要る変化を1件ずつ（頁・一覧・CONST）持つ。
  アプリは前の版からいまの版までの項目を走査して、まだの頁と一覧に反映させる。台帳に頁や一覧の変化が無い版上げでは、頁を作り直さない。
  1.7.0〜1.7.6 の変化も記入した（図の部品・ゴールのブレット・施策の ID・完了の札・飛び先・一覧の行）
- 頁の `<html>` に `data-loop-ver`、一覧の LOOPS ブロックに `<!-- list-ver -->` を足した。どの版の作りまで反映したかの印で、アプリがまだの頁を見分ける
- 合わせると、画面から ttyd の説明・「⬆ アップデート」のボタン・コピーの知らせが消える
- `shell-update.py` は `chat-pane.sh` を配らない。プロジェクトに残っている `loops/chat-pane.sh` と `loops/.chat-sessions` は消さない（`.chat-sessions` はアプリが読む）
- 版の正は `VERSION`。`.claude-plugin/plugin.json` の `version` と、殻の雛形の版の表示をそれに合わせる。
  スキルの版が上がると、アプリはチャットを新しい会話にし、この CHANGELOG の要点を最初に出し、殻と共通の部品の入れ替えをダイアログで聞く
- どこからも使われていなかった画像（`assets/img/`）を消した

  はじめが無いときは塗らない（中立の灰色）。**既存の頁の見た目が変わる**（上がっている施策は赤から緑に）

  聞く文は `shell-update.py` が画面の言葉で出し（何が変わるか・何分か・「数字や施策の記録は消えません」）、AI はそのまま見せる

- 実行中の施策にも飛び先（`id="trial-L06-T03"`）を付ける。本文の「T03」から実行中の施策へ飛べる。

- 右ペインが開いているとき、モーダルがペインの下に潜らない
- ボタンを 📋 付きの破線の札にし、「押しても実行されない」と見た目で伝える
- 見出し「トライ中の施策」を「施策の実行」に（図の4段階と同じ言葉に揃えた）
- 規約: 導入・現在地報告の締めは「まず施策を1つ選んで、『指示する』から『これをやって』と送ってください」
- **施策の進み方を変えた**（実行 → 評価の移行が分かりにくかった）
  - 施策案を拾ったとき、効果の数字は聞かない。代わりに実現手順のチェックリスト（⬜）をその場で TRIAL に出す。全部 ✅ で実施完了
  - 実施が終わっても TRIAL に止まる。RECORD を先に作らない（同じ施策が2か所に見えていたのをやめた）
  - TRIAL の「指示する」に札「完了にして（評価に移す）」。これがユーザー起点の唯一の入口
  - 「完了にして」のときに初めて「効果を数字で確かめますか」→ 見る数字・判定日・予想を聞き、RECORD に移す
  - TRIAL は何件でも並べられる（「1ループに1つ」と「待つ／入れ替える」の二択を廃止）
  - 予想を聞くのは「完了にして」のときだけ。それより前に AI から数字や測定の話を持ちかけない

既存プロジェクトの `index.html` には、`/rising-loop` で「使い方を追加して」と頼めば `assets/template.html` から写す（移行は不要）。
